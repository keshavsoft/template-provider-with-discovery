Express.js Routing & Table Documentation

A simple, story-based explanation of how Express.js, routing, HTTP methods, and application tables work together.

1. Introduction

This documentation explains how the Express.js application is organized and how different routes are connected with different tables. The purpose is to make the backend structure easy to understand, especially for a developer who is new to the project.

The application uses Express.js as its backend framework. Express receives requests from the client, identifies the requested route, executes the required operation, communicates with the appropriate table or data source, and finally sends a response back to the client.

Express.js Backend framework
Routing Directs requests
Methods Define operations
Tables Store application data
Basic concept: Client → Route → Method → Table → Response

2. What is Express.js?

Express.js is a lightweight Node.js web framework used to build servers and APIs. It helps receive requests, process them through routes and middleware, and return responses.

3. What is Routing?

Routing decides what should happen when a particular URL and HTTP method are requested. In simple words: Route = URL + HTTP Method + Handler.

More Information →

4. What Sub Routing

A Sub Route is a route defined inside another Router to organize related APIs into smaller groups. It helps keep large applications clean by separating routes based on their functionality or resource.

More Information →

5. Why Do We Use Different Routes?

A real application normally contains many different types of data. For example, an application may contain Customers, Products, Orders, Employees, Suppliers, and Payments.

Each type of data can have its own route group. This keeps the application organized and makes it easier to maintain. 

/api/customers
/api/products
/api/orders
/api/employees
/api/suppliers
/api/payments

Instead of placing every operation into one large file, the routes can be separated logically according to the table or business functionality they handle.

6. Tables in the Application

A table represents a particular type of data used by the application. The exact tables depend on the project, but a typical application may contain the following:

Table Purpose
Customers Stores customer-related information.
Products Stores product-related information.
Orders Stores order-related information.
Employees Stores employee-related information.
Suppliers Stores supplier-related information.
Payments Stores payment-related information.
Project-specific note: Replace the example table names above with the actual tables used in the application.

7. Table and Routing Relationship

One table can have multiple routes and methods. For example, a Customers table may have GET, POST, PUT, and DELETE operations.

8. HTTP Methods

HTTP methods describe the operation a route performs. GET reads, POST creates, PUT updates, and DELETE removes data.

More Information →

9. Table-wise Examples

8.1 Customers Table

The Customers table is responsible for storing customer-related information. Different routes are provided to retrieve, create, update, and delete customer records.

Method Route Purpose
GET /api/customers Get customer records.
GET /api/customers/:id Get one customer.
POST /api/customers Create a customer.
PUT /api/customers/:id Update a customer.
DELETE /api/customers/:id Delete a customer.

8.2 Products Table

The Products table contains product-related information. Its routes allow the application to manage product records.

Method Route Purpose
GET /api/products Get product records.
GET /api/products/:id Get one product.
POST /api/products Create a product.
PUT /api/products/:id Update a product.
DELETE /api/products/:id Delete a product.

8.3 Orders Table

The Orders table contains information about customer orders. Different routes are used to manage order records.

Method Route Purpose
GET /api/orders Get order records.
GET /api/orders/:id Get one order.
POST /api/orders Create an order.
PUT /api/orders/:id Update an order.
DELETE /api/orders/:id Delete an order.
