Express.js Routing & Table Documentation

A simple, story-based explanation of how Express.js, routing, HTTP methods, and application tables work together.

1. Introduction

This documentation explains how the Express.js application is organized and how different routes are connected with different tables. The purpose is to make the backend structure easy to understand, especially for a developer who is new to the project.

The application uses Express.js as its backend framework. Express receives requests from the client, identifies the requested route, executes the required operation, communicates with the appropriate table or data source, and finally sends a response back to the client.

Express.js Backend framework
Routing Directs requests
Methods Define operations
Tables Store application data
Basic concept: Client → Route → Method → Table → Response

2. What is Express.js?

Express.js is a lightweight web framework built on top of Node.js. It provides a simple way to create web servers, APIs, routes, and middleware.

Instead of manually handling every incoming HTTP request, Express allows the application to define routes and specify what should happen when those routes are called.

Client ↓ Express Server ↓ Route ↓ Required Method ↓ Table / Data Source ↓ Response

For example, when a client sends GET /api/customers, Express looks for the matching GET route and executes the logic associated with it.

3. What is Routing?

Routing means deciding what should happen when a particular URL and HTTP method are requested.

A route normally consists of two important parts: the HTTP method and the URL path. 

GET     /api/customers
POST    /api/customers
PUT     /api/customers/:id
DELETE  /api/customers/:id

Although the GET and POST examples use the same URL, they perform different operations because the HTTP methods are different.

Routing in simple words: Routing tells Express which code should handle a particular request.

4. Why Do We Use Different Routes?

A real application normally contains many different types of data. For example, an application may contain Customers, Products, Orders, Employees, Suppliers, and Payments.

Each type of data can have its own route group. This keeps the application organized and makes it easier to maintain. 

/api/customers
/api/products
/api/orders
/api/employees
/api/suppliers
/api/payments

Instead of placing every operation into one large file, the routes can be separated logically according to the table or business functionality they handle.

5. Tables in the Application

A table represents a particular type of data used by the application. The exact tables depend on the project, but a typical application may contain the following:

Table Purpose
Customers Stores customer-related information.
Products Stores product-related information.
Orders Stores order-related information.
Employees Stores employee-related information.
Suppliers Stores supplier-related information.
Payments Stores payment-related information.
Project-specific note: Replace the example table names above with the actual tables used in the application.

6. Table and Routing Relationship

The most important concept in this application is that one table can have multiple routes or methods.

For example, the Customers table can be accessed using GET, POST, PUT, and DELETE operations. 

Customers Table
      ↓
---------------------------
GET
POST
PUT
DELETE
---------------------------

Therefore, one table does not necessarily mean one API endpoint. A single table may have several routes, with each route responsible for a different operation.

Example story: A user opens the customer screen and requests customer information. The client sends a GET request. Express receives it and identifies the Customers route. The route retrieves the required records from the Customers table and sends them back to the client. If the user creates a new customer, the client instead sends a POST request. The same Customers route group now performs a create operation.

7. HTTP Methods

GET Retrieve Data

GET is normally used to retrieve existing information. 

GET /api/customers
Client ↓ GET /api/customers ↓ Customers Route ↓ Customers Table ↓ Customer Records ↓ Response

POST Create Data

POST is normally used to create a new record. 

POST /api/customers
Client ↓ POST /api/customers ↓ Customers Route ↓ Customers Table ↓ New Customer Created ↓ Response

PUT Update Data

PUT is normally used to update an existing record. 

PUT /api/customers/10
Client ↓ PUT /api/customers/10 ↓ Customers Route ↓ Find Customer 10 ↓ Update Customer ↓ Customers Table ↓ Response

DELETE Remove Data

DELETE is used to remove an existing record. 

DELETE /api/customers/10
Client ↓ DELETE /api/customers/10 ↓ Customers Route ↓ Customers Table ↓ Customer Deleted ↓ Response

The Customers table is responsible for storing customer-related information. Different routes are provided to retrieve, create, update, and delete customer records.

9. Additional Routes

Not every table is limited to basic CRUD operations. Depending on the application's business requirements, a table may have additional routes.

For example, the Orders table may provide routes such as: 

GET /api/orders
GET /api/orders/:id
POST /api/orders
PUT /api/orders/:id
DELETE /api/orders/:id
GET /api/orders/customer/:customerId
GET /api/orders/status/:status

All of these routes may work with the same Orders data, but each route has a different purpose.

Important: When documenting the real application, count both the number of tables and the number of routes/methods associated with each table.

10. Complete Request Flow

The complete application flow can be understood through the following structure:

CLIENT │ │ HTTP Request ↓ EXPRESS SERVER │ ↓ ROUTER │ ┌──────────┼──────────┐ ↓ ↓ ↓ Customers Products Orders │ │ │ ↓ ↓ ↓ METHOD METHOD METHOD │ │ │ ↓ ↓ ↓ TABLE TABLE TABLE │ │ │ └──────────┼──────────┘ ↓ RESPONSE │ ↓ CLIENT

Step-by-step explanation

  1. The client sends an HTTP request.
  2. Express receives the request.
  3. Express checks the URL and HTTP method.
  4. The matching route is selected.
  5. The route identifies the required operation.
  6. The required table or data source is accessed.
  7. The operation is completed.
  8. The result is returned as a response to the client.

11. Summary

The Express.js application can be understood through four main levels:

Express.js ↓ Routing ↓ HTTP Methods ↓ Tables
Component Responsibility
Express.js Provides the backend framework and handles requests.
Routing Determines which code should handle a request.
HTTP Methods Define the operation such as retrieving, creating, updating, or deleting data.
Tables Store the application's data.
Final story: The Express.js server acts as the entry point of the backend. When a request arrives, routing determines where that request should go. The HTTP method explains what operation needs to be performed. The selected route then works with the appropriate table or data source. After the operation is completed, the result is returned to the client as a response.
