About OpenAPI

A simple explanation of OpenAPI and how it helps developers describe, understand, test, and work with HTTP APIs.

1. What is OpenAPI?

OpenAPI is a standard way to describe an HTTP API. It provides a structured description of the API so that developers and tools can understand how the API works.

Simple story:

Think of an API as a restaurant. The API is the kitchen, and the OpenAPI document is the menu. The menu tells customers what is available, what information is needed, and what they can expect in return.

2. Why Do We Need OpenAPI?

As an API grows, it becomes difficult to remember every URL, HTTP method, parameter, request body, and response. OpenAPI provides one structured place to describe these details.

Without OpenAPI: Developers may need to search through source code to understand how an API works.
With OpenAPI: Developers and tools can use the API description as a common reference.

3. API Description

OpenAPI describes important parts of an API, including its paths, HTTP methods, parameters, request bodies, responses, and data structures.

API │ ├── URL / Path │ ├── HTTP Method │ ├── Parameters │ ├── Request Body │ ├── Response │ └── Data Structure

4. How OpenAPI Works

A developer writes an OpenAPI description that represents the API. Tools can then read this description and use it to understand the API.

OpenAPI Document ↓ API Description ↓ OpenAPI Tools ↓ ┌──────┼────────┐ ↓ ↓ ↓ Docs Tests Client Code

This means the same API description can be useful for developers, testers, documentation tools, and other API-related tools.

5. Simple OpenAPI Example

Suppose our Express.js application has the following API: 

GET /api/v1/doctors/showAll

An OpenAPI document can describe this endpoint like this: 

openapi: 3.0.3

info:
  title: Doctors API
  version: 1.0.0

paths:

  /api/v1/doctors/showAll:

    get:
      summary: Get all doctors

      responses:

        '200':
          description: Doctors retrieved successfully

The OpenAPI document tells us that the API has a particular path, uses the GET method, and can return a successful response.

6. Benefits of OpenAPI

Understand APIs Developers can understand how an API works without reading all of the backend code.
Generate Client Code OpenAPI descriptions can be used by tools to generate client code.
Create Tests API descriptions can help tools and teams create and validate API tests.

The OpenAPI Initiative also highlights common tool support, shared developer knowledge, and abstraction of API descriptions as important benefits. :contentReference[oaicite:1]{index=1}

7. OpenAPI File

An OpenAPI description is commonly written in YAML or JSON. The file describes the API in a structured format. 

openapi.yaml

openapi: 3.0.3

info:
  title: Doctors API
  version: 1.0.0

paths:
  /api/v1/doctors:
    get:
      summary: Get doctors
Important: OpenAPI describes the API. It does not replace your Express.js routes or controllers.

8. OpenAPI with Express.js

In an Express.js project, Express handles the actual API requests, while OpenAPI can describe those APIs in a standard format.

Client ↓ Express.js ↓ Router ↓ Controller ↓ Database OpenAPI ↓ Describes the API above

So OpenAPI and Express.js have different responsibilities. Express.js runs the API, while OpenAPI describes the API.

9. Summary

The simple story:

Express.js is responsible for running the API. OpenAPI provides a standard description of that API. The description explains the available URLs, methods, parameters, requests, responses, and data structures.

Because the API description follows a standard format, people and tools can understand and work with the API more easily.
